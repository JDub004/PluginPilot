## Scoring model

Each factor is scored 1-5 and normalised; weights sum to 100:

| Factor | Weight | Meaning |
|---|---|---|
| pain | 20 | How much the problem hurts (money/time/risk) |
| freq | 12 | How often one user hits it |
| fit | 10 | Would a user naturally ask ChatGPT about this? |
| native | 13 | Native-substitution defence: 5 = plain ChatGPT clearly cannot do it |
| mcp | 8 | Can a small set of deterministic tools execute it? |
| wtp | 10 | Willingness to pay |
| comp | 10 | Competition (5 = little) |
| mvp | 7 | MVP simplicity (5 = 1-3 days) |
| ret | 5 | Retention / repeat use |
| dist | 5 | Distribution outside ChatGPT (SEO, social, communities) |

Changes vs. the brief: ChatGPT fit lowered 15→10 and a new **native** factor (13) added, because the official guidelines and the platform trend make "ChatGPT could do this alone" the single most common way a plugin dies. Frequency lowered 15→12 and MVP 10→7 to make room.

**RISK_SCORE** (0-100) combines legal/regulatory, privacy, platform-absorption and data-access risk. **EXPECTED_VALUE = score × (1 − risk/200)**.

All factor values are analyst judgements based on the evidence in MARKET_RESEARCH.md. They are hypotheses to be replaced with measured data.
